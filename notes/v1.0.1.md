# 1.0.1 — Le mod ne change pas. Tout ce qui l'entoure, oui.

**Résumé en une phrase** : le monde généré est identique à la 1.0.0 ; cette version refond l'installation, la configuration et la documentation.

---

## Ce qui change pour toi

**Rien dans le jeu.** C'est le point le plus important de cette note : si tu installes la 1.0.1, tu obtiens exactement le même monde qu'en 1.0.0. Mêmes ressources au sol, mêmes recettes, même arbre technologique, même kit de départ. La seed 5 produit toujours le même résultat.

En interne, un seul caractère a bougé : le numéro de version dans `info.json`. Le contenu du mod est identique au caractère près.

Ce qui change, c'est **tout ce qui entoure le mod** : on peut désormais jouer sans installer Python, la configuration se valide au lieu de planter mystérieusement, et la documentation existe enfin.

## ⚠️ Une action si tu avais touché la configuration

C'est la seule chose qui demande un geste de ta part.

`config/settings.yaml` n'existe plus. Il est remplacé par deux fichiers :

| Fichier | Rôle | Modifiable |
|---|---|---|
| `config/defaults.yaml` | tous les réglages par défaut | non |
| `config/user.yaml` | tes surcharges | oui, facultatif |

**Si tu n'avais jamais modifié `settings.yaml`**, tu n'as rien à faire. Le nouveau système lit les mêmes réglages, aux mêmes valeurs.

**Si tu l'avais modifié**, recopie tes surcharges dans `user.yaml`. Le format est identique : mêmes clés, mêmes sections. Un simple copier-coller, rien à réécrire.

```
cp config/settings.yaml config/user.yaml     # tes réglages survivent
```

Et si une clé est inconnue, une valeur hors bornes ou contradictoire, la génération s'arrête sur un message qui dit ce qui ne va pas. Avant, ces erreurs passaient parfois et produisaient un monde bizarre sans explication. Les valeurs qui étaient auparavant dispersées dans le code sont désormais toutes dans `defaults.yaml` : 286 lignes de réglages lisibles, contre 163 lignes avant.

## Installer, deux voies

### Sans Python — trois étapes

1. Télécharge le `randputF_1.0.1.zip` attaché à cette page.
2. Copie-le tel quel dans ton dossier `mods`.
3. Active `randputF` dans le menu Mods de Factorio.

Le zip contient le mod complet, déjà généré, seed 5 comprise. **52 Ko.** Pas besoin de Python, pas de ligne de commande.

Le chemin du dossier `mods` dépend de ton système :

| Système | Chemin |
|---|---|
| Windows | `%APPDATA%\Factorio\data\mods` |
| Linux | `~/.factorio/mods` |
| macOS | `~/Library/Application Support/factorio/mods` |
| Steam Flatpak | `~/.var/app/com.valvesoftware.Steam/data/Factorio/mods` |

### Avec l'outil — pour une autre seed

```bash
pip install .
randputf generate --seed <VOTRE_SEED>
```

L'installation empaquette `mod/`, `data/` et `config/`. Sous Windows, dans un `venv`, les exécutables sont dans `Scripts\` et non `bin/`.

### Quand le mod n'apparaît pas

C'est le problème le plus fréquent, et il a presque toujours la même cause : le zip est resté dans `Downloads` au lieu d'être **extrait puis copié** dans `mods`, ou le dossier porte encore le nom du fichier zip. Factorio ne lit pas un `.zip`, il lit un dossier. La section dépannage du README couvre aussi les fours qui affichent un avertissement, les seeds injouables et le cas d'une erreur de configuration.

## Un zip cent fois plus léger

Le zip de release est passé de **5,2 Mo à 52 Ko**.

La cause : `seed.graph.html`, une vue de debug de la seed, y était encore embarqué. Ce n'est pas nécessaire pour jouer — c'est un outil d'inspection. Il a été retiré du zip, et du témoin de déterminisme par la même occasion.

## L'outillage

Quatre-vingt-dix commits, cinquante-sept fichiers, dont 4 200 lignes ajoutées.

Le cœur du travail n'était pas visible : la génération a été réorganisée dans `tool/service.py`, et les prototypes `easeup`, `recursive`, `nonfinite_randomisation`, `usage`, `starter`, `relay` et `craft_quantity` ont été repris. **Aucun effet sur le monde généré** : le témoin est identique. Le but était qu'une interface graphique puisse appeler exactement le même code que la ligne de commande, sans le réécrire.

La publication est maintenant entièrement automatique. Pousser `dev` vers `master` déclenche la construction, les tests, la création du tag et la publication. Les tests sont bloquants : une version ne peut pas sortir sur une suite rouge.

## Ce qui est garanti

| Garantie | Mesure |
|---|---|
| Déterminisme | le contenu d'une seed donnée ne change jamais : vérifié en CI à chaque commit |
| Solvabilité | 1501 graines balayées (0 à 1500), 1501 victoires, 0 échec |
| Tests | 722 tests, exécutés avant chaque publication |

Le témoin de déterminisme est une empreinte du contenu généré. La commande suivante doit rendre la même valeur, sur n'importe quelle machine :

```
randputf witness --seed 5 --expect ce428c2140ec7031f9604637ecf70cbc
```

Si elle diffère, ce n'est pas un bug du mod : c'est que l'outillage a changé sous tes pieds, et il faut le savoir.

## Ce que cette version ne fait pas

Voici ce que la 1.0.2 ou plus tard apportera, et qu'il ne faut pas attendre ici :

- **Pas d'interface graphique.** Le randomizer reste une ligne de commande.
- **Pas d'exécutable `.exe` Windows.** Prévu, pas fait.
- **Pas de support des mods tiers** (Krastorio, Py, Space Age). Hors périmètre, comme annoncé.
- **Pas de nouvelle mécanique de jeu.** Ni bâtiment, ni ressource, ni recette ajoutée : le contenu vanilla est randomisé, pas étendu.

Si tu cherchais l'un de ces éléments, cette version n'est pas faite pour toi.

## Détails techniques

Repliés ici parce qu'ils concernent le maintien du projet plus que le joueur.

**Pourquoi 1.0.1 et pas 1.1.0 ?** Le changement de configuration est visible par l'utilisateur : en semver strict, il mériterait un numéro mineur. Cette version sort en **1.0.1 par choix du mainteneur**, parce que le format de migration est identique et qu'aucune valeur par défaut ne change. Le semver reprend ses règles strictes dès la version suivante.

**Pourquoi le témoin a changé alors que le mod n'a pas changé ?** L'empreinte porte sur l'arborescence du zip, dont la racine contient le numéro de version (`randputF_1.0.1`). Un bump change donc l'empreinte même si le contenu est identique. C'est documenté dans [docs/witness.md](../docs/witness.md).

**Numérotation.** La 1.0.1 avait déjà été publiée, puis retirée, et le numéro réemployé. Aucun contenu n'a été distribué au public de manière durable. Elle n'a jamais existé pour personne.

**Branches.** `master` reçoit désormais la totalité de l'arbre de `dev` — code, tests et documentation — afin que le tag et le paquet publié soient reproductibles depuis le dépôt seul.

## Si tu upgrades : la liste

1. Télécharge le zip, ou mets à jour via `pip install .`.
2. Si tu avais modifié `config/settings.yaml` : recopie-le en `config/user.yaml`.
3. Supprime l'ancien `config/settings.yaml`.
4. Vérifie que le mod apparaît dans la liste. S'il n'y est pas, extraction avant copie.
5. Joue. Ta seed fonctionne comme avant.

Rien d'autre à faire.
