# 1.0.1 — Documentation mise à jour et configuration en deux YAML

**Ce que c'est** : un randomizer total pour Factorio 2.0. Il vide le tech-tree
et les recettes vanilla et régénère tout : ressources au sol, lacs de fluides,
recettes (entrées et sorties), coûts, catégories de bâtiments, ordre de
déblocage, kit de départ — en garantissant à chaque graine un parcours valide
jusqu'à la fusée. Aucune graine « en boîte noire » : chaque tirage est nommé,
isolé et rejouable.

**⚠️ Changement de configuration — migration requise**

`config/settings.yaml` est **remplacé** par deux fichiers :

- `config/defaults.yaml` — tous les réglages par défaut. Source unique, non
  modifiable.
- `config/user.yaml` — vos surcharges, facultatives.

La génération lit la config fusionnée et la **valide** : type, plage,
`min <= max`, contraintes croisées. Une clé inconnue ou une valeur impossible
est une erreur explicite, jamais un défaut silencieux.

*Si vous aviez modifié `settings.yaml`* : recopiez vos surcharges dans
`user.yaml` (mêmes clés, mêmes sections). Le format est identique.
`settings.yaml` n'est plus lu.

**Plus aucune valeur en dur dans le moteur** : prototypes, générateurs, CLI et
pipeline lisent tous leurs valeurs depuis le YAML.

**🔒 Déterminisme vérifiable**

```
randputf witness --seed 5 --expect 4f4bde847babcc6a5557a6633b08f6ce
```

Le témoin **change** au bump de version (le préfixe racine du zip contient
`randputF_<version>`) — mais ici il change **aussi** parce que la seed 5 est
touchée par le correctif d'auto-sélection des fours (voir plus bas) : le contenu
du mod pour la seed 5 n'est plus identique à celui de la v1.0.0. Le détail de la
canonisation est dans `docs/witness.md`.

**🐛 Correctif — deux recettes four sur le même ingrédient**

Les fours (`stone-furnace`, `steel-furnace`, `electric-furnace`) n'ont pas
d'écran de choix de recette : à ingrédients égaux, Factorio retient la première
venue et la suivante était **inatteignable**. Le générateur impose désormais
des **ingrédients disjoints** par four (re-tirage à la création, correction en
aval par la passe d'usage), les deux recettes restant disponibles. Validé sur
**2000 seeds** (zéro recette ombragée) et couvert par deux tests dédiés.

**📈 Difficulté comparée à vanilla**

Nouvelle commande `randputf compare` (et sortie `seed.difficulty.html` pendant
`generate`) : la difficulté cumulée de la seed, tech par tech, en ressources
brutes, superposée à celle d'une partie vanilla. Utile pour mesurer l'effet du
mod sur le coût de progression. Le graphe est **interactif** : survoler une tech
affiche son nom, son coût propre, le cumul et les items débloqués (pour les deux
courbes) ; un clic épingle, la légende masque une série, et les tableaux par tech
mettent le point correspondant en évidence.

**📦 Installation — deux voies**

*Sans Python, en trois étapes* : télécharge le `randputF_1.0.1.zip` attaché à
cette release, copie-le tel quel dans ton dossier `mods`, puis active `randputF`
dans le menu Mods. Le zip contient le mod complet déjà généré (52 Ko, seed 5) :
rien à installer, aucune commande. Le dossier `mods` selon ton système est dans
le README.

*Pour une autre seed*, il faut l'outil : `pip install .` (embarque `mod/`,
`data/` et `config/`) puis `randputf generate --seed <S>`.

**Garanties mesurées** : 722 tests, invariants de solvabilité, rejoueur « fake
player » 1501/1501 victoires, témoin de déterminisme vérifié octet-pour-octet
en CI.
