# 0.0.1 — Documentation mise à jour et configuration en deux YAML

**Ce que c'est** : un randomizer total pour Factorio 2.0 (base, sans Space Age).
Le tech-tree et les recettes vanilla sont vidés puis régénérés : ressources au
sol, lacs de fluide, recettes (entrées et sorties), coûts, catégories de
bâtiments, ordre de déblocage et kit de départ. Chaque graine suit un parcours
valide jusqu'à la fusée. Aucune graine « en boîte noire » : chaque tirage est
nommé, isolé et rejouable.

Cette note décrit l'état publié sous le tag `v0.0.1`. L'état courant, qui vise
Factorio 2.1, est décrit dans [`docs/release.md`](../docs/release.md).

**Changement de configuration — migration requise**

`config/settings.yaml` est remplacé par deux fichiers :

- `config/defaults.yaml` — tous les réglages par défaut, source unique non
  modifiable ;
- `config/user.yaml` — surcharges facultatives.

La génération lit la configuration fusionnée et la valide : type, plage,
`min <= max` et contraintes croisées. Une clé inconnue ou une valeur impossible
est une erreur explicite, jamais un défaut silencieux. Les surcharges de
`settings.yaml` sont recopiées dans `user.yaml` : les clés et les sections
restent identiques. `settings.yaml` n'est plus lu. Aucune valeur n'est codée en
dur dans le moteur : prototypes, générateurs, CLI et pipeline lisent tous leurs
valeurs depuis le YAML.

**Déterminisme vérifiable**

```bash
randputf witness --seed 5 --expect c9566134864507d900f65806ade277d9
```

Le contenu du mod pour la seed 5 est inchangé depuis la v0.0.0, mais le témoin
change au bump de version : la racine canonique `randputF_<version>` fait partie
des entrées hachées. Le md5 ci-dessus est celui de la v0.0.1, pas celui de la
v0.0.0. Le détail de la canonisation figure dans
[`docs/witness.md`](../docs/witness.md).

**Installation**

L'outil Python est installé avec `pip install .` (embarquement de `mod/`,
`data/` et `config/`), puis une seed est générée avec
`randputf generate --seed <valeur>`. Le mod assemblé va dans `output/mods/`, les
rapports HTML dans `output/reports/<source>/`. Aucun artefact généré n'est suivi
dans git.
