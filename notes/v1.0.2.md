# 1.0.2 — Notes de release automatisées et dépôt clarifié

**Correctif de documentation et d'outillage** — aucun changement de
comportement du randomizer. Le contenu du mod pour la seed 5 est identique à
celui de la v1.0.1.

**Ce qui change**

- **La release GitHub se publie avec sa note et son titre, du premier coup.**
  Jusque-là, `release.yml` créait la release avec un titre automatique
  (« randputF <version> ») et un simple lien « Full Changelog » ; la note
  devait être collée à la main après publication. Le workflow lit désormais
  `notes/v<version>.md` et publie exactement ce contenu, avec le titre pris sur
  la première ligne du fichier.
- **Une release sans note ne peut plus passer.** Si `notes/v<version>.md` est
  absent du tag, le workflow échoue explicitement au lieu de publier une note
  vide.
- **Le modèle de branches est documenté et appliqué** : `dev` porte le travail
  en cours, `master` porte l'historique intégré. Une release est le **commit de
  fusion** de `dev` dans `master` ; le bump de version se fait dans `dev`, donc
  jamais de push direct sur `master`.

**Documentation**

- `README.md` / `README_EN.md` : la description du modèle de branches est
  corrigée (elle décrivait un état périmé).
- Les notes de chantier (plans, idées, notes de révision) sont regroupées dans
  `atelier/`, absent des tags.
- `notes/README.md` explique la convention d'écriture des notes.

**🔒 Déterminisme vérifiable**

```
randputf witness --seed 5 --expect <md5 de la v1.0.2>
```

Le hash **change à chaque bump de version** (le préfixe racine du zip contient
`randputF_<version>`), même si le contenu du mod ne change pas. Le hash à jour
est dans `.github/workflows/ci.yml`. Le détail de la canonisation est dans
`docs/witness.md`.

**📦 Installation** : `pip install .` (embarque `mod/`, `data/` et `config/`)
puis `randputf generate --seed <S>`, ou télécharger le zip attaché.

**Garanties mesurées** : 722 tests verts, invariants de solvabilité, rejoueur
« fake player » 1501/1501 victoires, témoin de déterminisme vérifié
octet-pour-octet en CI.
